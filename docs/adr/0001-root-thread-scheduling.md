# Root Thread Scheduling and Ownership

Accepted. Top-level Roots may be configured per Root type as `MainThread` or `DedicatedThread`; existing Server configurations and Unity remain on the World-driven main thread by default. A DedicatedThread Root owns one thread for its full lifecycle and update phases, while child Roots inherit the parent owner. The World publishes a shared time snapshot and independent update pulses; a Root may hold at most one pending pulse, with excess pulses coalesced and counted. The RootManager remains the authoritative Root registry, while the scheduler owns execution; cross-Root mutations and ETTask completions return to the target or originating Root owner. Shared services are initialized before Root threads start and disposed after they stop. Invalid configuration, startup failure, or an unhandled Root exception fails the Server rather than silently falling back.

This preserves single-thread ownership of mutable Root state while allowing configured Roots to progress independently without global phase barriers. Correctness and isolation tests are required; performance measurements inform explicit per-Root configuration but impose no automatic threshold. Thread-pool scheduling and full Server graceful shutdown remain separate future decisions.
