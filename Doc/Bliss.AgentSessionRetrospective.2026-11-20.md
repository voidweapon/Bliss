## 候选改进（按优先级）

### 1. 高：审查流程与提交审批不匹配

**证据：** 当时的 `implement` 定义要求实现后审查再提交；`code-review` 描述支持工作区审查，但实际步骤只接受 `git diff <fixed-point>...HEAD`。未提交实现的三点差异为空，本轮经用户批准先提交，审查随后发现四个问题，另行修复并再次申请提交。

**建议：** 为审查技能增加显式的工作区模式，覆盖已暂存、未暂存及选定的未跟踪文件，并固定审查基点和补丁范围。保留现有已提交差异模式；提交审批前审查最终补丁，修复后的变化应再次核对。

**验收：** 在没有新增提交、但有上述三类改动的场景中，审查可完整读取选定补丁；无改动时正确报告空范围；不会为了获得差异擅自创建提交。

**落点：** 生效的 `implement`、`code-review` 技能定义及其调用流程。技能可能位于用户目录而非仓库，修改前确认实际生效版本和修改范围。

**状态（2026-11-20）：** 已将工作区审查流程写入项目文档 `Doc/Bliss.WorktreeCodeReviewWorkflow.md`，并在根 `AGENTS.md` 添加导航；用户目录中的第三方技能保持未修改。临时 Git 仓库验证覆盖暂存与未暂存改动、显式选择的未跟踪文件、重命名、删除、空范围和范围外排除。

### 2. 高：已有检查缺少自动执行入口

**证据：** 仓库已有分析器、服务端单元与 gameplay 集成测试，以及客户端和服务端的 Core 程序集依赖边界测试。复盘时未发现仓库内的 CI 工作流；本地 Git hooks 只有示例文件，且没有配置 `core.hooksPath`。该观察不代表已核实组织级或外部 CI 配置。

**建议：** 将现有检查接入明确的自动化入口和 CI，优先复用而非重写规则。Unity 检查使用具备项目 Editor 版本、许可及所需原生依赖的执行环境。

**验收：** 新提交或 PR 能触发现有检查；失败阻断交付并保留诊断。环境或许可缺失必须明确报告，不得把跳过检查视为通过。

**现有入口：**

**状态（2026-11-20）：** 已达成首阶段 CI 设计共识，采用公开仓库和必需的 .NET 状态检查；范围与取舍见 [ADR-0001](../docs/adr/0001-public-repository-for-required-dotnet-ci.md)。仓库可见性和 CI 工作流尚未更改。

### 3. 中：性能实验记录仍依赖人工

**证据：** 已有性能敏感工作流程，但本轮部分路径没有修改前的可比基线，运行配置或准备阶段也发生变化，无法据此判断性能变化。

**建议：** 增加统一的基准运行入口，记录代码版本、工作区差异标识、负载、准备方式、运行参数、环境、结果和警告。比较前校验实验条件；新组件没有旧实现时允许明确标记“无可比基线”，而不是编造对比。

**验收：** 两次实验的来源和条件可追溯；条件不匹配时拒绝直接生成性能提升结论；保留短迭代、离群值和未覆盖路径等限制。

**落点：** `BlissBenchMark/` 和 [性能敏感组件开发流程](Bliss.PerformanceSensitiveWorkflow.md)。

### 4. 中：普通 Release 构建会修改被跟踪的分析器 DLL

**证据：** `Bliss.ProjectRule/Bliss.ProjectRule/Bliss.ProjectRule.csproj` 的 `CustomAfterBuild` 在 Release 构建后自动复制 DLL 到 `Unity/Assets/CodeAnalyzer/Bliss.ProjectRule.dll`。本轮基准构建多次触发该副作用，需要人工比对产物再恢复。

**建议：** 将构建分析器与发布分析器到 Unity 分为显式步骤或受控的 MSBuild 开关，避免普通测试和基准运行顺带更新该文件。

**验收：** 普通验证不修改被跟踪的 Unity 分析器 DLL；显式发布仍能生成并更新正确产物。检查运行前后的工作区差异，保留用户原有修改。

### 5. 中：技能加载失败被过早解释为未安装

**证据：** 之前工具返回 `Skill not found` 后，代理未完整执行已有排错流程便断言技能未安装。此次重新检查时，加载工具仍未识别 `retro`，但用户技能目录中已有可读取的定义；不能据此反推该文件在更早时刻也已存在。

**建议：** 技能诊断同时检查工具注册状态和两个定义目录，分别报告“工具未识别”“定义不存在”或“依赖不可用”。遵循已有排错流程，不继续堆叠同义提醒。

**验收：** 工具未识别但定义存在时，能够按目录优先级读取定义并检查依赖；必要依赖不可用时停止并报告实际阻碍，不跳过步骤。

**落点：** [Skill 加载排错](Bliss.AgentSkillTroubleshooting.md)、技能发现和诊断入口。

**证据：** 根目录、Server、Unity 的 `AGENTS.md` 重复维护通用规范，部分命名例外不一致。客户端处理指南已存在，但这些入口文件中缺少明确的触发式导航。用户在会话中补充了 Entity/System 分工及避免闭包、lambda 的偏好。

**建议：** 保持规范的单一来源：可机械判定的规则优先由现有分析器或检查工具执行；职责分工和必要例外等判断性约定供审查使用。`AGENTS.md` 保留简短导航、目录特有约束和必要审批要求。

**验收：** 新会话能从适用的 `AGENTS.md` 找到相关规范和客户端处理指南；重复规则及例外冲突得到处理，现有约束不因整理而丢失。
