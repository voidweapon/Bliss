## 候选改进（按优先级）

### 1. 高：验证启动窗口的消息和失败行为

**证据：** 用户选择让 Main 在其自身初始化 handler 返回后 Ready，再由独立 handler 串行创建配置 Root。#37 限制初始化期间的 EntitySystem 更新，但外网和内网消息准入、致命失败协调分别属于 [#38](https://github.com/voidweapon/Bliss/issues/38)、[#39](https://github.com/voidweapon/Bliss/issues/39)、[#40](https://github.com/voidweapon/Bliss/issues/40)。在这些能力完成前，Main 提前 Ready 可能使消息入口更早工作；启动失败也不会自动触发 #40 的进程退出。

**建议：** 在相关 issue 的约定接缝验证初始化中的消息拒绝、Ready 后既有路由和启动失败后的处理。按 #40 的计划，真实子进程退出码和 watchdog 自动回归留待 Server E2E 工程；不以进程内测试替代进程级结论。

**验收：** 各 issue 的行为测试覆盖其相应入口及状态转换；真实进程级测试具备后，验证启动失败、非零退出和 watchdog 期限。尚未实现或无法运行的场景明确标注，不宣称完整启动闭环已交付。

### 2. 高：处理构建中的依赖安全公告

**证据：** 本次服务端构建及测试输出报告 `Bliss.ProjectRule` 使用的 Scriban 6.2.1 存在 `NU1902` / `NU1903` 公告。构建成功不等于已评估实际可利用性或升级兼容性。

**建议：** 单独核实当前公告、依赖路径和受影响范围，评估可用修复版本；在确认升级兼容后更新依赖并复用现有构建、分析器测试和 CI。评估自动化依赖告警与处理策略时先检查已有机制，避免重复建设。

**验收：** 记录所评估的依赖路径、公告和处置结果；若升级，相关构建、分析器测试和 CI 通过，且目标公告不再适用。若暂不能升级，记录原因、风险和后续处理责任。

### 3. 中：保护不可热更新程序集的二进制接口

**证据：** #37 审查发现为 `RootManager.Create` 增加可选参数会改变编译后的方法签名，而共享 Model 可热更新、Core 不可热更新。实现已恢复原重载，并增加签名回归测试；该测试不代表所有跨程序集接口均已覆盖。

**建议：** 评估对不可热更新程序集的公开接口建立自动化兼容性检查，明确哪些程序集、已发布基线和允许破坏的发布场景受保护。优先复用现有测试和 CI；先验证其是否能检测该次实际签名变化。

**验收：** 选定范围和基线有明确维护方式；移除或修改受保护签名时检查失败，保留原重载时通过。检查结果区分有意且获批准的破坏性发布与意外变更。

### 4. 中：降低工作区审查和边界验证的重复成本

**证据：** #37 多轮双轴审查发现了更新期间挂载门禁、嵌套 GameplayWorld 调度和二进制接口等遗漏，修复后按项目流程重新固定并审查完整补丁。已有 [工作区审查流程](Bliss.WorktreeCodeReviewWorkflow.md) 要求记录基点、精确范围、未跟踪文件和审查前后快照；本轮这些步骤主要由人工命令执行。

**建议：** 在后续涉及调度或生命周期时，根据实际需求提前设计重入、嵌套调度及兼容性行为测试。另行评估工作区快照工具，复用现有流程而不修改第三方 skill 或放宽审查、提交批准要求。

**验收：** 若实施快照工具，覆盖现有流程列出的暂存与未暂存、显式选择的未跟踪文件、重命名、删除、空范围和范围外排除场景；能检测审查前后补丁及状态变化，且不更改工作区或暂存状态。测试选择依据具体任务，而非无差别增加测试矩阵。
